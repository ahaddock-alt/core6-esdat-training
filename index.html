Project setup — projects, sites, and COC preparation

Module 1 of 5 — Before field work begins

ESdat organises all environmental data under a Project → Site → Location hierarchy. Getting this right before field work begins determines whether your data can be found, compared, and reported correctly. Errors at setup propagate through every table you will ever produce from that project.

Projects vs. sites — understanding the structure

The Project is the billing unit. It corresponds to a specific phase of work and is the identifier the laboratory uses to route data into ESdat. The Site is the geographic unit — the physical location where sampling occurred. One Project has one Site in most cases, but a project spanning multiple separated areas requires a distinct Site for each area. Discuss data segregation with your PM at project kickoff — restructuring after data is loaded is painful.

Access levels — confirm before you need them

Only staff with Admin or Scheduler access can create or edit Projects and Sites. Check your access level before the field program. Do not wait until lab results arrive to discover you cannot create the project — that costs at minimum 24 hours while results sit unrouted in the LabSync queue.

Creating a project and site

  1. Click Create Project in the top-right corner of ESdat. Complete required fields (marked *). The Project ID must exactly match what you will write on the COC.
  2. After saving the Project, add a Site. Set the coordinate system now — this is your only clean opportunity. For multi-site projects, create a separate Site for each geographic area after discussing the approach with your PM.
  3. Confirm the Project status is set to Active. Inactive projects accept no new data. Lab uploads, sample edits, and depth entries all silently fail or error against an inactive project.
  4. Record the Project ID and Site ID somewhere accessible before going to the field — both go on every Chain of Custody.
⚠Create the ESdat Project and Site before the lab sends anything. ALS automatically sends data to the LabSync address when it has your Project ID. If the Project does not exist in ESdat when they send, the upload errors and must be manually reassigned later.

Chain of Custody (COC) — field preparation

The COC is what connects your physical field samples to ESdat. Two fields on it are non-negotiable for automatic ESdat loading:

  • Job # / PO #: Enter the 5-digit project number and 2-digit phase — e.g. 00653-03. This is the routing key ESdat uses. Also enter it in the PO number field for invoicing. A wrong number here means your data does not reach the correct project.
  • Report format / EDD: Mark EDD (ESdat format) on the COC. Without this, the lab sends only a PDF — nothing for ESdat to import automatically. ALS already knows to send ESdat format; for any other lab, confirm this in writing before the field program. Add it to your project mobilisation checklist.
ℹCore6 LabSync address: ESdat_CA+Core6@ESdatLabSync.net. When a lab sends ESdat-format files (EDD + PDF COA + COC) to this address with the correct Project ID, ESdat validates and queues the report for your review automatically.

Information to collect in the field — needed before ESdat import approval

  • Top and bottom depth of every soil, sediment, and surface water sample (range preferred over point)
  • Screen interval top and bottom for every groundwater monitoring well (mbgs)
  • Sample type for every sample — Normal, Field Duplicate, Equipment Blank, Trip Blank, etc.
  • Parent sample ID for every duplicate — required to link parent-duplicate pairs in ESdat
  • Lab COA number (Lab Ref) — needed to match the upload in Lab Uploads to your COC
